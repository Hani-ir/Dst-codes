# مرحله 0 — بررسی v2rayN و روش پیشنهادی (منتظر تأیید)

تاریخ: 2026-10-23

## محدودیت این بررسی (مهم)
این بررسی روی **کد منبع رسمی** انجام شد (v2rayN کامیت `57f17d5`، 2026-10-20؛ v2rayNG کامیت `01b4630`، 2026-10-22)،

`tools/inspect-v2rayn.ps1` (فقط‌خواندنی) روی سیستم خودتان تأیید شود.

## یافته‌ها: v2rayN ویندوز (از روی کد)

| مورد | محل | نکته |
|---|---|---|
| تنظیمات | `guiConfigs\guiNConfig.json` | سرور فعال = فیلد `IndexId` |
| لیست سرورها و اشتراک‌ها | `guiConfigs\guiNDB.db` (SQLite) | جدول سرورها: `ProfileItem` (Remarks, Address, Port, Id, Subid, ...). لینک اشتراک هم اینجاست |
| هسته‌ها | `bin\` (xray، sing-box، ...) | هسته‌ها را می‌شود مستقل اجرا کرد |
| تک‌نمونه | Mutex به اسم `v2rayN` | فقط یک نسخه از برنامه باز می‌شود |

یافته‌های کلیدی:
1. **نسخه دسکتاپ هیچ API یا راه کنترل از بیرون ندارد** (نه پورت، نه named pipe، نه خط فرمان برای انتخاب سرور).
2. v2rayN تنظیمات را **در حافظه نگه می‌دارد و موقع ذخیره بازنویسی می‌کند**. پس اگر وقتی برنامه باز است
   `guiNConfig.json` را عوض کنیم، یا تغییر دیده نمی‌شود یا بعداً پاک می‌شود. **تغییر سرور از راه فایل
   یعنی بستن v2rayN، ویرایش، و باز کردن دوباره** (چند ثانیه قطعی).
3. **با هر آپدیت اشتراک، همه سرورهای آن اشتراک حذف و دوباره ساخته می‌شوند** (`AddBatchServers` →
   `RemoveServersViaSubid`)، پس `IndexId` ثابت نمی‌ماند. سرور را باید با **آدرس + پورت + UUID/پسورد** پیدا کرد، نه با ID.
4. آپدیت خودکار اشتراک **داخل خود v2rayN هست** (`AutoUpdateInterval` به دقیقه، برای هر اشتراک جدا).
   ولی **سوئیچ خودکار به بهترین سرور ندارد**.
5. پروژه رسمی جدیدی به اسم **`v2rayN.WebAPI`** هست: نسخه بدون پنجره (headless) با REST API کامل،
   از جمله `subscriptions/update`، `profiles/{id}/latency`، `speedtests` و `profiles/{id}/select`.
   **ولی جایگزین برنامه دسکتاپ است، نه کنترل‌کننده آن**: طبق README نباید هم‌زمان با دسکتاپ روی یک
   پوشه داده اجرا شود، و رابط گرافیکی هم ندارد.

## گزینه‌ها برای فعال کردن سرور از بیرون

| | روش | مزایا | معایب و ریسک‌ها |
|---|---|---|---|
| **A** | v2rayN دسکتاپ + اسکریپت ما: تست با xray.exe خود v2rayN، و تغییر سرور با «بستن ← ویرایش `IndexId` ← باز کردن» | همان v2rayN آشنا با پنجره و آیکن tray می‌ماند | هر سوئیچ ۳ تا ۱۰ ثانیه قطعی؛ وابسته به ساختار DB/JSON که ممکن است با آپدیت v2rayN عوض شود؛ ریسک خراب شدن فایل (با بکاپ قبل از هر ویرایش کم می‌شود) |
| **B** | به‌جای دسکتاپ، `v2rayN.WebAPI` و کنترل کامل با API رسمی | تمیزترین و پایدارترین راه؛ سوئیچ بدون بستن برنامه؛ بدون دستکاری DB | **پنجره v2rayN دیگر در کار نیست**؛ پروژه تازه است؛ پروکسی سیستم/TUN و پایداری‌اش باید روی سیستم شما تست شود |
| **C** | بدون v2rayN: اسکریپت ما خودش xray را اجرا می‌کند | کنترل کامل، ساده‌ترین منطق | با خواسته شما («فعال کردن در v2rayN») جور نیست؛ پروکسی سیستم را هم باید خودمان مدیریت کنیم |

**پیشنهاد من: A** چون دقیقاً همان چیزی است که خواستید (v2rayN بماند). **B** را به‌عنوان مسیر دوم
نگه می‌دارم، اگر قطعی چندثانیه‌ای موقع سوئیچ اذیت کرد یا ساختار فایل‌ها با آپدیت‌ها مدام عوض شد.

### طرح اجرایی روش A
1. **آپدیت اشتراک:** همان قابلیت داخلی v2rayN با `AutoUpdateInterval = 5`. اسکریپت ما لیست را مستقیم
   از `guiNDB.db` (فقط خواندن) برمی‌دارد. لینک اشتراک **در فایل config ما هم لازم نیست**، چون v2rayN
   خودش آن را دارد. اگر بخواهید اسکریپت خودش لینک را بخواند، لینک در `config.json` جدا می‌ماند و هیچ‌وقت لاگ نمی‌شود.
2. **تشخیص آلمان:** اسم/پرچم (`🇩🇪`، `DE`، `Germany`، `آلمان`) **و** GeoIP. هر دو باید تأیید کنند.
3. **تست:** برای هر سرور یک config موقت xray روی پورت محلی جدا، و درخواست `generate_204` از داخل آن
   (تأخیر واقعی). همه موازی و با timeout.
4. **تست سرعت:** فقط روی ۳ سرور برتر، و فقط وقتی قرار است سوئیچ کنیم (توضیح در بخش ریسک‌ها).
5. **سوئیچ با hysteresis:** فقط اگر سرور فعلی خراب شده، یا سرور جدید **حداقل ۲۰٪ تأخیر کمتر** دارد
   **در دو دور پشت‌سرهم** (تا یک تست خوش‌شانس باعث قطعی نشود).
6. اولویت با آلمان و بعد آمریکا؛ وقتی روی آمریکا هستیم، هر دور آلمان هم تست می‌شود و به محض سالم شدن برمی‌گردیم.
7. اجرا هنگام ورود به ویندوز با Task Scheduler. اگر v2rayN بسته بود، بازش می‌کند.
8. قبل از هر ویرایش، از `guiNConfig.json` بکاپ گرفته می‌شود.

## ریسک‌ها و فرض‌های اشتباه که باید بدانید
1. **«آی‌پی آلمان با 178 شروع می‌شود» فرض ضعیفی است.** بلوک `178.0.0.0/8` بین ده‌ها کشور تقسیم شده
   (ایران، روسیه، ترکیه و ...). پس فقط می‌تواند نشانه کمکی باشد، نه معیار.
2. **اگر سرورها پشت CDN باشند (مثلاً Cloudflare)، GeoIP آی‌پی CDN را نشان می‌دهد، نه سرور واقعی.**
   آن‌وقت فقط اسم قابل اعتماد است. باید ببینیم آدرس سرورهای شما IP مستقیم است یا دامنه/CDN.
3. **منبع GeoIP:** سرویس‌های آنلاین (ip-api و مشابه) از ایران ممکن است فیلتر باشند و آی‌پی سرورها را به
   شخص ثالث می‌دهند. پیشنهاد: دیتابیس آفلاین (`geoip.dat` خود v2rayN یا GeoLite2).
4. **تست سرعت هر ۵ دقیقه روی ۳ سرور حجم زیادی مصرف می‌کند** (مثلاً ۳ × ۱۰ مگابایت × ۲۸۸ بار در روز ≈ ۸.۶ گیگ در روز).
   پیشنهاد: تست سرعت فقط موقع سوئیچ، یا حداکثر هر ۳۰ تا ۶۰ دقیقه.
5. **ساختار DB/JSON رسمی و مستند نیست.** با آپدیت v2rayN ممکن است عوض شود. اسکریپت باید نسخه را چک
   کند و اگر ساختار ناآشنا بود، **هیچ تغییری ندهد** و فقط لاگ کند.
6. **ساخت exe:** PyInstaller را باید روی خود ویندوز اجرا کرد (از لینوکس نمی‌شود). بعضی آنتی‌ویروس‌ها
   exeهای PyInstaller را اشتباهی مشکوک تشخیص می‌دهند.
7. **حالت TUN:** اگر از TUN استفاده می‌کنید، باز کردن دوباره v2rayN ممکن است دسترسی Administrator بخواهد.

## اطلاعاتی که لازم دارم (قبل از کدنویسی)
1. خروجی `tools/inspect-v2rayn.ps1` (فایل `v2rayn-inspect.txt`).
2. یک نمونه از اسم سرورها (مثل `🇩🇪 Germany-03`). **لینک اشتراک را نفرستید.**
3. پروتکل‌ها چیست؟ (vless/vmess/trojan/ss/hysteria2/...) و آدرس سرورها IP است یا دامنه؟
4. Python روی سیستم هست؟ (برای ساخت exe لازم است، ولی کاربر نهایی به Python نیازی ندارد.)
5. انتخاب روش: A، B یا C.

## اندروید (v2rayNG): خلاصه اولیه
(بررسی کامل بعد از تأیید ویندوز)
- **داخلی دارد:** آپدیت خودکار اشتراک با WorkManager (حداقل بازه اندروید **۱۵ دقیقه** است، پس ۵ دقیقه ممکن نیست)،
  «تست خودکار بعد از آپدیت»، «مرتب‌سازی بعد از تست»، «حذف سرورهای خراب»، و شروع خودکار هنگام بوت (`BootReceiver`).
- **از بیرون قابل کنترل:** فقط `TaskerReceiver`، یعنی **روشن/خاموش کردن** و **روشن کردن با یک GUID مشخص**.
  تست تأخیر یا خواندن نتیجه‌ها از بیرون **ممکن نیست**.
- **نتیجه صادقانه:** کنترل کامل با Tasker/MacroDroid شدنی نیست. یا به تنظیمات داخلی (تست ← مرتب‌سازی) بسنده می‌کنیم،
  یا یک اپ کوچک جدا لازم است که خودش تست کند و با Tasker سرور را عوض کند.
